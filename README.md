# AES-128 encryption core in VHDL

A small, readable AES-128 encryption core written in VHDL, with a self-checking testbench, test vectors
generated by an independent implementation (OpenSSL), mutation testing, and synthesis estimates for three FPGA
families. Everything runs with free tools (GHDL, Yosys, Python): no license is needed.

The core encrypts one 128-bit block per operation (ECB, no mode of operation) in 11 clock cycles.

## Results

All results below were obtained in simulation or synthesis. **Nothing was run on a board.**

| Check | Result |
|---|---|
| FIPS 197 examples (appendix B and C.1) | pass |
| 762 vectors from a file (single-bit sweeps on plaintext and key, 500 random cases) against OpenSSL | pass |
| Protocol: latency of 11 cycles, `busy` high while working, one-cycle `done`, key latched, `start` ignored while busy, reset in the middle of an encryption | pass |
| Mutation testing: 27 deliberate bugs injected in the VHDL | 27 detected |
| S-box table in the VHDL equals the table computed from its mathematical definition | pass |

Synthesis estimates (GHDL + Yosys, no place-and-route, see `synth/report.txt`):

| Target | Result |
|---|---|
| Lattice iCE40 | 5230 LUT4 and 261 flip-flops. The iCE40 UP5K has 5280 logic cells, so the core alone would take about 99% of it. |
| Intel Cyclone V (adaptive LUTs) | about 1440 ALUTs and 261 flip-flops |
| Xilinx 7 series | 1438 LUTs, 261 flip-flops, 528 MUXF7 and 208 MUXF8 |

These are estimates from Yosys. The official numbers for a device come from its vendor tool (for example Quartus
for Altera/Intel), which was not used. No clock frequency was measured.

## How it works

Iterative architecture: one AES round per clock cycle. The 16 bytes of the state go through 16 S-boxes at each
round, and the round key is computed on the fly with 4 more S-boxes, so no key memory is needed.

```
start --> [ state = plaintext XOR key ]            1 cycle
          [ SubBytes, ShiftRows, MixColumns, AddRoundKey ] x 9      9 cycles
          [ SubBytes, ShiftRows, AddRoundKey ]                      1 cycle  (no MixColumns)
done  --> ciphertext on block_out
```

### Interface (`rtl/aes128_core.vhd`)

| Port | Direction | Meaning |
|---|---|---|
| `clk` | in | clock |
| `resetn` | in | synchronous reset, active low |
| `start` | in | pulse for one cycle while `busy = 0`: latches `key` and `block_in` and starts |
| `key` | in | 128-bit key |
| `block_in` | in | 128-bit plaintext block |
| `busy` | out | high while an encryption is running |
| `done` | out | high for exactly one cycle when the result is ready |
| `block_out` | out | ciphertext, valid from `done` until the next `start` |

A `start` pulse while `busy = 1` is ignored. Byte 0 of a block (the first byte of the message in usual hexadecimal
notation) is bits 127 to 120. Latency: 11 clock cycles from the edge that samples `start` to the cycle where
`done` is high, so one block of 128 bits every 11 cycles.

### Files

- `rtl/aes_pkg.vhd`: S-box, `xtime`, SubBytes, ShiftRows, MixColumns, round constants and one step of the key
  schedule, as VHDL functions (FIPS 197, chapter 5).
- `rtl/aes128_core.vhd`: the core, a state machine around those functions.

## Run it

You need [GHDL](https://github.com/ghdl/ghdl) (on Ubuntu or in WSL: `sudo apt install ghdl`), Python 3, and for
the synthesis estimates Yosys.

```sh
sh sim/run.sh                       # compile and run the testbench, prints AES TEST PASSED
python3 sim/mutation_check.py       # 27 deliberate bugs, each one must be detected
python3 scripts/gen_sbox.py --check # the S-box table in the VHDL matches its definition
sh synth/synth_all.sh               # resource estimates, writes synth/report.txt
```

To regenerate the test vectors (they are already in the repository): `pip install cryptography`, then
`python3 scripts/gen_vectors.py`. The expected ciphertexts come from OpenSSL through the `cryptography` package,
which is independent from the VHDL code. The testbench also contains the two FIPS 197 examples typed again from
the standard.

## Verification in detail

1. **Vectors**: the file `vectors/aes128_vectors.txt` has 762 cases: the two examples of FIPS 197, all-zero and
   all-one inputs, 128 plaintexts with a single bit set, 128 keys with a single bit set, and 500 random cases
   (fixed seed). Single-bit sweeps exercise the diffusion of every input bit and every step of the key schedule.
2. **Protocol checks** in the testbench: latency, `busy` and `done` behaviour, key latching, ignoring `start`
   while busy, reset during an operation.
3. **Mutation testing** (`sim/mutation_check.py`): 27 small changes (wrong S-box entry, wrong reduction constant
   in `xtime`, wrong ShiftRows or MixColumns, wrong round constants, missing RotWord, key schedule not chained,
   wrong number of rounds, MixColumns in the last round, `start` accepted while busy, key not latched, `done`
   missing or too long, reset ignored, `busy` stuck low...). The first version of the testbench detected 26 of
   them: it never checked that `busy` is high while the core works. A check was added and all 27 are now detected.

## Limitations

- Encryption only: no decryption, no AES-192 or AES-256, no modes of operation (ECB on a single block).
- **Not protected against side-channel attacks.** The S-boxes are plain lookup tables in logic and nothing is
  masked or balanced. Do not use it where an attacker can measure power, timing or electromagnetic emissions.
- Synthesis estimates only: no place-and-route, no timing analysis, nothing run on a board, no Quartus or Vivado run.
- The core is large for small devices (about 99% of the logic cells of an iCE40 UP5K). The S-boxes dominate the
  area; storing them in block RAM or computing a column at a time would reduce it, at the cost of more cycles.
- No bus wrapper (AXI4-Lite or other): the core has a simple start/busy/done interface.
- Tested with GHDL 4.1.0 only (VHDL-2008).
